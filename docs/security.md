# Security and Compliance

How SQLLens protects access, credentials, SQL and model files, what data it keeps, and the known gaps. Status as of 2026-11-12: the security audit of `main` (findings SEC-1 to SEC-12) and the Phase SEC fixes (SEC-T1 to SEC-T9). Report a vulnerability as described in [SECURITY.md](../SECURITY.md).

## Deployment model and trust boundaries

SQLLens is a local-first, single-instance tool (D-008). It is meant to run on a developer's machine and be opened at `http://localhost:3000`.

| Boundary | What crosses it | Control |
| --- | --- | --- |
| Browser → app | Pages and `/api/*` calls | Session cookie; `src/proxy.ts` allows only known `Host` values and blocks cross-origin writes |
| App → SQL Server / PostgreSQL | SQL text, parameters, login | Only when `allowLiveExecution` is `true`; TLS on and certificates verified by default |
| App → Hugging Face | Model repository downloads | Signed-in user, rate limited; optional `HF_TOKEN` from the environment |
| App → model worker | Prompt text (contains the SQL) over local IPC | Forked plain Node process with only `PATH`, `HOME`, `NODE_ENV` |
| App → disk | SQLite database, `audit_logs/`, `data/appconfig.json`, model files | Local file permissions of the user running the app |

No SQL, prompt or result is sent to an external AI service: models run locally.

Exposing the app beyond localhost (`SQLLENS_ALLOWED_HOSTS`) is not a supported production setup yet: HTTPS is not required (SEC-7). Put it behind a TLS reverse proxy you control if you must, and set `NODE_ENV=production` so the cookie is `Secure`.

## Controls in place

- **Sign-in.** Users are created with `npm run admin:set-password` (user `admin`, password at least 12 characters). Passwords are hashed with scrypt and compared in constant time; unknown users are checked against a dummy hash. Logins are rate limited (429).
- **Sessions.** 256-bit random tokens in an HttpOnly, SameSite=Lax cookie (`Secure` in production), 7-day server-side expiry, real logout. The database stores only the SHA-256 of each token. Every API route except login requires a session.
- **Ownership.** Audit records, shares, feedback and run evidence are read and written only for the session that created them.
- **CSRF and DNS rebinding.** `src/proxy.ts` rejects unknown `Host` headers and state-changing requests from another origin.
- **Headers.** Every response carries a Content-Security-Policy (`default-src 'self'`, `frame-ancestors 'none'`, `object-src 'none'`), `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: no-referrer` and a restrictive `Permissions-Policy`; `X-Powered-By` is off.
- **Rate limits.** Every write route is rate limited per session; logins per username and overall (see `docs/api.md`).
- **Prompt files.** Prompt settings may only name `.md` files inside `data/prompts/` (symlinks resolved), so a setting cannot make the app read other files.
- **Share links.** 32 random bytes, expire after `shareTtlHours` (1-720, default 24), can be revoked, and still need a signed-in session. A share returns only the stored result.
- **SQL execution.** Off by default (`allowLiveExecution: false`; simulation only). Parameters are bound; catalog queries use parameters and the procedure name is bound. `queryTimeoutMs` limits each run. Credentials are never stored in audit records and are scrubbed from run logs.
- **Model output.** Model JSON is validated before it is returned. Review returns findings only; Refactor's SQL is checked (it must not write to tables the original does not, or use undeclared variables) and is never executed. Index DDL is generated by the server, not taken from the model.
- **Model downloads.** Model ids are sanitised and must stay inside `downloadDirectory`, which must be inside the home folder (symlinks resolved). Files are validated before use; GGUF or Safetensors files are never treated as ONNX.
- **Logs.** Logged errors are scrubbed: connection-string secrets, tokens, quoted names and SQL, and `host:port` addresses are removed, and messages are capped at 500 characters.
- **Dependencies.** `npm audit --omit=dev` reports no vulnerabilities (Next.js 16.4.6, Transformers.js 4.3.2, an `@azure/identity` override for the SQL Server driver; unused Prisma and npm packages removed).
- **Secrets.** The Hugging Face token comes only from `HF_TOKEN`; a legacy `apiKey` in the config is dropped. `.gitignore` covers `.env*`, `keys.md`, `downloads/models/` and `audit_logs/`; the database lives outside the repository. No secret is tracked in git.

## Data inventory and retention

| Data | Where | Contains | Kept |
| --- | --- | --- | --- |
| Audit records | `sqllens.db` (`SQLLENS_DB_DIR`, default `../../sqllens_db`) | SQL text, parameters, results, plans, messages, host and database names, prompts (which contain the SQL), model output, feedback | `retentionDays` (default 90); a user can delete their own record on its page |
| Sessions | `sqllens.db` | SHA-256 of the session token, user, expiry | Expired sessions are purged once no record belongs to them |
| Users | `sqllens.db` | Username, scrypt hash | Until removed by hand |
| Execution logs | `audit_logs/` (`SQLLENS_AUDIT_LOG_DIR`) | One file per run, owner-only (0600): the SQL's SHA-256 and length (the text itself only when `logSqlText` is `true`), parameters, messages, raw output | `retentionDays` |
| Settings | `data/appconfig.json` | Settings only, no secrets | Until changed |

Retention runs when the server starts and once a day (`src/instrumentation.ts`). Treat the database and `audit_logs/` as sensitive: they can contain business data returned by procedures. `logSqlText` is `false` by default; turn it on only when the procedure text is not confidential. Never use production data or production credentials with live execution.

## Live execution risk

With `allowLiveExecution` on, procedures and batches run for real against the database you connect to. They are not wrapped in a rolled-back transaction, and a batch may `COMMIT` (decision D-036), so a run can change data. Use a development or test database and a login with only the rights the procedure needs.

## Logging

Server errors are logged to the console through `src/lib/redact.ts`, which removes known secret keys from logged objects and scrubs message text (see Controls). Prompts and model output are not logged; they are stored in the audit record.

## Known gaps

From the 2026-11-12 audit. Fixed by Phase SEC: SEC-1 (dependencies), SEC-2 (prompt paths), SEC-3 (headers), SEC-4 (retention, delete, private logs, `logSqlText` off), SEC-6 (hashed tokens, session purge), SEC-8 (rate limits), SEC-10 (log scrubbing), SEC-12 (stray script). Still open:

| ID | Severity | Gap |
| --- | --- | --- |
| SEC-5 | medium | Live runs can change data: accepted risk (D-036). Execute & Audit SP shows a warning when live execution is on |
| SEC-7 | low | HTTPS not required for hosts other than localhost (backlog) |
| SEC-11 | low | Audit records are not tamper-evident (backlog) |
| — | low | Dev-only tooling (`typescript-eslint` → `minimatch`) has moderate advisories; it never runs in the app |

## Dependency updates

Run `npm audit --omit=dev` before each release and after dependency changes. Upgrade packages with a critical or high advisory before release, and record exceptions in `.team/decisions.md`.

# Changelog

## Unreleased

- Review Stored Procedure redesigned (RV-1 to RV-5): the model and result format moved to Settings (Review model, Review result format; Automatic picks the best instruction-tuned model, not the first alphabetically). Reviews are findings only; the rewritten procedure comes from Refactor, which removes the long rewrite where small models looped. Evidence is a searchable picker of your runs ("#57 dbo.Proc · database · grade · time · reads · date") with a "What the model will see" preview: timings, reads per table, whether the plan is included, and the exact JSON sent. Telemetry now works with small models. The page has numbered steps, a live status with an elapsed clock, Cancel, and results in Summary, Findings and Index ideas tabs.
- Fix: the dev server crashed (SIGILL) during Generate refactor and Review on Apple M5. Local models now run in a separate Node worker process (`scripts/inference-worker.mjs`); a runtime crash fails only that run with a 502 and the server keeps running.
- Audit record page redesigned (AD-1 to AD-3): Back to Audit and Open Execute & Audit SP buttons; a Record block (type, number, time, engine, model used, status, simulated); a high-level Report for each record type; Related records ("Refactored from run #N", "Refactored in #M"); Prompt (template, closing instruction, full text); and the stored Request and Response, each folded away with Copy. New Review, Compare and Refactor records store the prompt sent to the model; a refactor made on Execute & Audit SP stores the run it came from (`sourceAuditId`). Older records say the prompt was not recorded.
- Reopen a saved run (AD-5): Open in Execute & Audit SP on an execution record opens `/execute?record=<id>`, showing that run's stored result tabs and the latest refactor saved from it, read-only (no login is stored, so Run again and Generate refactor are hidden). A refactor record opens the run it came from. Start a new run returns to an empty form.
- Refactor and review answers from small models: a column list written as text ("a, b") or a single index recommendation written as an object is accepted (recommendations are still checked against the SQL's tables and columns); a ```sql block after the JSON counts as the rewrite when the `<rewritten_procedure>` tags are missing; the original SQL handed back unchanged is reported as "the model returned the original SQL unchanged" instead of a refactor. While a refactor runs, the panel says what it is doing (reading the definition, sending N lines with the run's verdict, hot tables and plan findings) and shows an elapsed-time clock.
- Model downloads now also fetch `tokenizer_config.json`, `chat_template.jinja`/`.json`, `special_tokens_map.json` and `generation_config.json` when the repository has them. Before, models downloaded through Manage Models had no chat template, so instruction-tuned models answered like base models. Re-download a model to get the files.
- Automatic refactor model: models with a chat template and instruction-tuned names (Instruct, -chat, -it) rank above larger base models.
- Refactor on Execute & Audit SP: the model is chosen in Settings (new "Refactor Model" dropdown of installed models; automatic picks an installed, compatible model with a chat template, instruction-tuned names (Instruct, Chat, -it) first, then the largest parameter estimate), and the refactor now sits inline in the Refactor tab, styled like the other result tabs, instead of a popup with its own model list.
- Refactor: when the original is a stored procedure, an answer without a `CREATE`/`ALTER PROCEDURE` statement (for example a small model's garbled "CRETELECT ...") is removed with status `invalid` and a message to retry or use a larger model, instead of being shown as usable SQL. The Execute screen's refactor tells the model the procedure runs on Microsoft SQL Server (T-SQL).
- Execute & Audit SP: the Database picker moved from Connect to Server to What to run. Connect now folds the connection to one line straight away ("Connected · server · login · N databases"), and the database is chosen next to the procedure.
- Prod-readiness verdict: with no targets set in Settings, runs are judged against the grade C limits (under 5,000 logical reads, under 1,000 ms) instead of always showing "INSUFFICIENT EVIDENCE: no targets set"; the reason says which limits were used (D-044).
- Execute & Audit SP: the sidebar link is named "Execute & Audit SP"; "Stored procedure" is the default choice; once a database is chosen, the procedure name field is a selection box with that database's stored procedures (`POST /api/execute/procedures`): its arrow opens the full list, typing filters it, any name can still be typed, and a Refresh button reloads it.
- Execute & Audit redesigned as four numbered steps (EX-1 to EX-7): 1 Connect to Server (folds to one line, "Connected · server · database · login", with Change, once a database is chosen; Trust server certificate under More options), 2 What to run (Stored procedure or SQL batch radios, a "Compare with an optimized version" checkbox, saved parameter sets folded away), 3 Run (Execute & Audit says why it is not ready yet), 4 Results (a one-line verdict, grade, time and reads, then tabs: Summary, Details, Raw output, Refactor; Comparison, Original, Optimized, Raw output in compare mode). Headings, landmarks, radio and checkbox controls, live status messages and plain-language help text throughout. To keep the page short: after a successful run, steps 1 to 3 fold to one bar (Edit setup, Run again); the Summary tab shows the top three recommendations and the full list has its own Recommendations tab; the grade table opens on demand; parameters are one line each under a single header row; the Run step stays pinned at the bottom of the screen while editing.
- Execute & Audit: the connection panel is laid out like SQL Server's "Connect to Server" dialog: Server type (SQL Server, first and selected, or Simulation; PostgreSQL is no longer offered there, PG-1), Server name and port, Authentication (SQL Server or Windows, P9-01, D-038: NTLM with domain, user name and password), Login or User name, Password, Database, Trust server certificate. Its Connect button checks the login and fills the Database list (`POST /api/execute/databases`, DB-1); it replaces "Test connection", so the screen no longer calls `POST /api/connections/test` (the route stays). A Windows login with Trust server certificate on shows a warning on the form.
- The Execute screen no longer has a Runs field. Each single-mode run on a real database executes a warm-up plus `measuredRuns` measured runs (default 2, so 3 executions), set under Settings → SQL execution; simulation and compare run once.
- `data/appconfig.json` is committed with `allowLiveExecution: true` at the user's request, so a fresh checkout can run procedures against a database.
- Compare and Refactor are off by default (`showCompare`, `showRefactor`); when off, the sidebar hides them and their pages say they are turned off in Settings (UX-A).
- Leaving a screen while an execution, review, comparison or refactor runs asks to cancel the task and leave, or stay; closing or reloading the tab gets the browser warning (`src/components/leave-guard.tsx`) (UX-B).
- Settings are grouped by category, and the prod-readiness targets and the maximum repeated runs can now be edited there (UX-C).
- The refactor on Execute & Audit opens in a large dialog; closing it while the model runs asks first and cancels the request (UX-D).
- One header, title, description and spacing style on every screen; section titles in one colour; requirement codes and colour-only emoji removed from titles (UX-E).
- Execute page: after a successful single run, a "Refactor Stored Procedure" panel generates a refactored version and index, view and other recommendation scripts with a local model, each in its own section with a copy button. The run's verdict, hot tables and plan findings are sent to the model as instructions (`src/lib/refactor-evidence.ts`). For a procedure run by name, its text is read with the new read-only `POST /api/execute/definition`. A refactored batch can be put into the Optimized editor ("Use as Optimized"); nothing runs until Execute is pressed. The Refactor page and the panel share `src/components/refactor/RefactorResultView.tsx`.
- The grade rationale names the metric that set the grade (for example "Graded D by logical reads 14,139 (grade C needs under 5,000)").
- One colour system on every screen: all pages and `globals.css` take their colours from `src/lib/theme-tokens.ts`. The orange, blue and purple accents are now a single cyan accent, and status, grade and verdict colours use a colour-vision-safe palette with a symbol or letter beside the colour (`src/lib/status-tone.ts`; `tests/unit/theme-consistency.test.ts`).
- Added the test stack: Vitest and Testing Library for unit and component tests, Playwright for end-to-end tests, and the `test`, `test:e2e`, and `typecheck` scripts (`package.json:12-14`; `vitest.config.mts`; `playwright.config.ts`). Decision D-009.
- Excluded `.agents/**` (vendored agent skills) from ESLint (`eslint.config.mjs`).
- Added versioned SQLite migrations (`src/db/migrate.ts`, `src/db/migrations/001_baseline.sql`) and the `SQLLENS_DB_DIR` setting. Decisions D-002, D-020, D-022.
- Ignored Python bytecode, `audit_logs/`, and Playwright output in `.gitignore`; removed tracked `.pyc` files from the index. Decision D-010.
- Corrected README, API, configuration, troubleshooting, and limitations docs to match the code.
- Added the squad team workflow files (`.team/`, `docs/team/`).
- Added model validation and download documentation.
- Documented API, configuration, security, testing, deployment, and limitations.
